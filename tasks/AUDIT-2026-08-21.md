## 2. Overall Health Assessment

**Architecture: strong.** Clean module layering (controller → service → repository), thin controllers, centralized validation, public/internal ID separation held end-to-end, Decimal money math end-to-end, disciplined parameterized raw SQL, race-safe stock/coupon guards added by the previous review wave, near-complete FK indexing, solid test pyramid (81 files / ~1040 tests).

**But the audit found one production blocker and a cluster of P1s:** the compiled artifact cannot boot; checkout can 500 on legitimate address data; login has no brute-force defense; tests destructively wipe the dev database; tokens leak into logs; and the rate limiter collapses behind any reverse proxy. A further theme is **invariant enforcement by convention instead of constraint** (primary images, address defaults, duplicate reviews, display_order) which breaks under concurrent admins/users.

Counts: **1 × P0, 6 × P1, 19 × P2, 27 × P3** new findings → tasks T-028…T-080.

## 4. Detailed Findings

### 4.1 Build & runtime

**T-028 (P0).** `src/config/database.ts:2` imports `"../generated/prisma/client"` without extension; tsconfig uses `module: ESNext` + `moduleResolution: bundler`, so tsc emits the specifier verbatim into `dist/config/database.js`. The generated client dir has no `package.json`/index resolution for Node's ESM loader → `node dist/index.js` fails with `ERR_MODULE_NOT_FOUND`. Dev works only because tsx is lenient; CI typechecks+builds but never boots the artifact. *Fix:* explicit `.js` extensions everywhere (or NodeNext resolution); add a CI boot smoke step.

### 4.2 Authentication & sessions

- **T-029 (P1):** `POST /auth/login` and `/register` carry only `validate()`; the sole protection is the global 100 req/15 min/IP limiter (in-memory store). Credential stuffing ≈9,600 guesses/day/IP, scaling linearly with distributed IPs.
- **T-036 (P2):** `changePassword` (users.service.ts:95-116) rotates the password but not outstanding `PASSWORD_RESET` tokens — a previously issued reset link stays valid for its full TTL and revokes all sessions again.
- **T-037 (P2):** `changeUserRole` counts admins then updates non-transactionally (admin.service.ts:175-182) — two concurrent demotions of the last two admins both pass the guard → zero admins left.
- **T-038 (P2):** OTP verify (users.service.ts:252-301) allows unlimited guesses per token within its 10-min TTL; success binds a victim's phone number to the attacker's account.
- **T-039 (P2):** `PATCH /admin/users/:id` writes attacker-chosen email/phone directly, keeps stale `email_verified_at`, no notification — then the public password-reset flow yields takeover.
- **T-046 (P2):** `SESSION_IDLE_TIMEOUT_MS = SESSION_TTL_MS = 30d` (constants/session.ts) makes the T-004 idle check unreachable while `expires_at > now`.
- **T-055/T-056/T-057/T-058/T-059/T-060 (P3):** racy single-use token claim (blind `update` by id); timing oracle on unknown-email logins; anonymous unsafe endpoints CSRF-skipped (login CSRF); soft-deleted accounts squat unique email/phone forever; registration is three non-transactional writes; assorted consistency debt (dead `is_current` column, magic `"ACTIVE"` string, mixed 400/404 invalid-token codes, `req.userId` holding a public id, `verifyPasswordReset` not re-checking account status/target email, no bcrypt 72-byte max).

Done well: 256-bit CSPRNG session/token material hashed at rest; uniform non-enumerable messaging; per-request role/status re-read so suspensions/demotions apply immediately; coherent revocation matrix; CSRF double-submit correctly bound to the session value.

### 4.3 Orders / cart / inventory

- **T-030 (P1):** address validators cap at 255 but `shipments.address_1/2` are VarChar(100) (schema.prisma:398-399); checkout copies verbatim (orders.service.ts:263-276) → Postgres 22001 → opaque 500 on the revenue path for affected users.
- **T-040 (P2):** only `addCartItem` takes the per-user advisory lock; update/remove/clear don't — interleavings with checkout produce P2025/null-deref 500s, worst case killing a valid checkout.
- **T-061/T-062/T-063 (P3):** positive `quantity_change` unbounded → int4 overflow 500; `releaseStock` result unasserted in the pending-cancel branch (every sibling op asserts); orders/inventory `search` unbounded length; gateway factory throws bare `Error`; per-user coupon limit relies incidentally on the checkout advisory lock (document it or add `FOR UPDATE`).

Verified sound: single-transaction checkout with lock-first ordering; atomic guarded stock/coupon ops with affected-count assertions; exhaustive terminal transition matrix with row lock before matrix read; consistent ROUND_HALF_UP(2) between catalog and snapshot; collision-free order numbers; no SQL injection in any raw fragment (values parameterized, sort columns whitelisted).

### 4.4 Catalog / reviews / addresses

- **T-041 (P2):** primary-image promotion computes state outside the tx; no partial unique index `(products_id) WHERE is_primary` → two primaries possible.
- **T-042 (P2):** PATCHing the current default to false leaves zero defaults even without races; concurrent creates/updates interleave clears; delete never promotes a successor.
- **T-043 (P2):** duplicate-review check is app-level only; no `@@unique([users_id, products_id]) WHERE deleted_at IS NULL` backstop → duplicates skew summaries.
- **T-044 (P2):** `%`/`_` act as wildcards in products/categories customer search, inventory admin search, and admin-users search (reviews module escapes correctly; T-013 tracks orders only).
- **T-045 (P2):** identical filters feed page query and `_avg/_count` aggregate → `?rating=5` returns `average_rating: 5`, `total_count` = 5-star count only.
- **T-064…T-070 (P3):** racy `display_order` uniqueness; soft-deleted slugs reserved forever + admin include_deleted list/detail mismatch; slug clamping/non-Latin policy; review-image provenance/orphans; product soft-delete retention policy (images, inventory, cart_items, reviews, links); barcode uniqueness decision; pagination tiebreakers on products/variants.
- **T-071 (P3):** `zip_code` vs `postal_code` split across addresses/shipments; ENHANCEMENTS.md also asks to drop `country` (Egypt-only delivery).

Verified sound: sort allowlists gate every ORDER BY; pagination uniformly capped; no internal-ID/deleted_at leaks in customer payloads; no N+1 patterns; visibility rules consistently filtered at repository level.

### 4.5 Infrastructure / database / CI / ops

- **T-031 (P1):** reset emails link to `${CORS_ORIGIN}/reset-password?token=…` but no such page/route exists — web recovery broken end-to-end.
- **T-032 (P1):** `.env` and `.env.test` point at the same dev schema; `cleanupTestData` runs `deleteMany({})` on catalog tables unconditionally — running tests nukes development data; nothing prevents pointing tests at staging/prod.
- **T-033 (P1):** no `app.set("trust proxy")` — behind nginx/LB/PaaS all clients share one bucket (self-DoS) and logs/sessions record proxy IPs.
- **T-034 (P1):** logger reads+parses+rewrites the entire pretty-printed JSON file per entry (O(n²) I/O, corruption risk, multi-instance unsafe); request logs include `req.originalUrl` → live verification/reset tokens persisted in never-rotated logs (contradicts docs/LOGGER.md).
- **T-047 (P2):** DATABASE.md mandates versioned migrations; none exist (db push only, `--accept-data-loss` in CI); 10 tables carry check constraints that `db push` cannot recreate in fresh environments — documentation/implementation conflict per AGENTS.md.
- **T-048 (P2):** `npm audit --omit=dev` → high advisories: deepmerge-ts <8 (GHSA-ggr8-5vv4-36mx) via prisma; fast-uri 3.0.0–3.1.4 (GHSA-7p8r-x3mc-p8w7).
- **T-049 (P2):** `payments.users_id` is the only FK column in the schema without an index.
- **T-050 (P2):** ci.yml triggers on `pull_request` only; multiple direct-to-main commits ran zero checks.
- **T-051/T-052/T-053 (P2):** HTML 404 fallthrough for unknown API routes; static health check placed behind the global limiter (LB probes will 429-flap); shutdown neither closes keep-alive sockets nor disconnects Prisma nor flushes queued crash logs.
- **T-054 (P2):** API_ENDPOINTS.md claims `{error:{code,message}}` envelope and `has_more` pagination that exist nowhere in code; `REVIEWS_REQUIRE_PURCHASE` flag state undocumented (folded here + T-080).
- **T-072…T-078 (P3):** verification tokens accumulate forever + cleanup CLI skips `$disconnect()`; verify pages interpolate server strings via innerHTML and serve without cache headers; implicit body limit/no HPP/no compression/unvalidated `x-request-id`/`validate()` clobbers query+params with undefined; single-origin CORS; dead `password_reset_tokens` table + `session_status` enum and TIMESTAMP-vs-TIMESTAMPTZ mix; missing `engines`, strictness flags, coverage thresholds, dead `@/*` alias; actions pinned by mutable tags, empty-secret failure mode, and **four workflows recorded in PROJECT_PROGRESS (pr-title, prisma-validate, audit, labeler) are absent from the repo** — only ci.yml exists.
- **T-079 (P3):** ENHANCEMENTS.md claims verified: current-email/current-phone rejection messages already implemented (users.service.ts:128-132, 217-221); "phone-number not working" and "duplicated email verification endpoint" need reproduction/triage.

Done well: `.env`/`.env.test` confirmed untracked; zod env validation fail-fast with no weak SESSION_SECRET default; helmet + CSRF + per-operation limiters present; FK indexing near-exemplary; operator CLIs with dry-run/batching/idempotence; layered test architecture with active flake remediation.
